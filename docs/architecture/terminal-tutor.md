# Terminal tutor

## Interactive workspace

The default terminal driver uses Bubble Tea, Bubbles, Lip Gloss, and Glamour. It presents a scrollable lesson, a pinned current question and answer box, searchable topics and sources, and progress. Wide terminals add a course sidebar; narrow terminals use a single column. The title gives the topic, its place in the course, and the step within the topic, such as `Topic 1 / 303 · Step 2 / 4`. `Alt+Left` and `Alt+Right` step through the topic on screen; at either end a second press moves to the neighboring topic that has steps, and landing on the current topic's last step restores the live question. Resumed copies and re-ask markers do not count as steps. See [0160](../decisions/0160-topic-history.md). Historical questions stay attached to their turn; a learner must return to the latest turn before submitting an answer.

Each model update handles an input or a completed command. An agent command receives a snapshot of the saved state and returns a new state after validation and persistence. The screen never blocks on model output. It permits one active turn while allowing local browsing. The worker owns no screen state. A mutex and cancellation boundary ensure worker shutdown finishes before the session lock is released.

The full-screen interface does not parse slash commands: text that starts with a slash is sent as a question. `Ctrl+N` means next: the next question while a quiz or probe has questions left, otherwise the next topic. `Ctrl+F` means more: more on the topic after a lesson, or more questions after a finished quiz, and it does nothing mid-quiz. See [0360](../decisions/0360-next-and-more.md). `Ctrl+F` extends a finished quiz, Home offers "Review a weak topic" when a topic has more incorrect and partial answers than correct ones, and the Sources list ends with every other file in the repository, so a search reaches any file. Plain mode keeps its commands. See [0320](../decisions/0320-no-slash-commands-in-the-interface.md). A lesson is reading and ends with no question. The composer under it is always a question box, and an action line above the composer offers `Ctrl+G` to quiz this topic, `Ctrl+F` for more on the topic, and `Ctrl+N` for the next topic, named by title. Only quiz and probe questions are pending questions, so only they are answered and reviewed. The session format version is 4. See [0300](../decisions/0300-course-flow.md). An answered turn groups the question answered, the learner's answer, and its feedback. A horizontal divider marks feedback even when the reply has no grade. The tutor stops after assessment or a skipped question; the next question is requested only on explicit Continue. Hints preserve the pending question. Follow-up questions during review keep the review stage. If the answered question is no longer in saved history, the interface shows the answer and feedback without inventing context. Plain mode uses `/continue` for the same boundary. Older graded replies may contain a next explanation and question; review hides that continuation and requests a fresh exercise when the learner continues.

`/probe` asks one short question on each of the first three topics after the overview that are not yet known. A correct answer marks the topic known; a partial, incorrect, or skipped answer does not. `/continue` asks the next probe question, then teaches the first unknown topic. Next-topic navigation skips known topics, and an incorrect answer later clears the mark. Starting a lesson or quiz leaves the probe. The probe is saved with the session, which is why the session format version is at least 3.

`/quiz` starts a quiz on the current topic, with a goal of 3, 5, or 10 questions from the Quiz length setting. The saved quiz holds the goal and generated questions with their outcomes. Only assessed answers or explicit skips complete a question; asking for a hint does not. `/continue` generates the next question until the goal is reached; `/extend` then increases the goal by the same length and generates one additional question. The question index is a list. Selecting a skipped or current question returns to it with no agent request, and answering replaces the skipped result in that slot once. Selecting the next slot generates it after review, and later slots are not selectable. Selecting an answered slot shows the turn that graded it and does not reopen it; the slot keeps the index of that turn, which shifts when history is trimmed. The active slot is saved with the quiz, which is why the session format version is at least 3. The title shows the question's position, such as `Question 2 / 5`, with the topic; the answered count stays in the sidebar. Topic changes leave the current quiz; restarting a quiz starts a new goal. Overall topic outcomes remain recorded independently.

A running request replaces the lesson pane with an explicit loading view and the existing spinner. It identifies the requested topic. A request on the current topic keeps Topics and this lesson's sources open. A request that moves to another topic hides the last lesson's sources, quiz goal, and shortcuts, holds Ctrl+S with a notice, names the requested topic in the sidebar, and keeps Topics open until the lesson arrives. Code browsing uses Chroma lexers compiled into the binary, with light and dark token palettes, a separate citation marker, and plain text fallback for unknown languages or `NO_COLOR`. A Markdown file has a second, rendered view that uses the same Glamour renderer as lessons; `v` switches views. A Markdown file always opens rendered. Every open marks a row: the view scrolls to the first words of the line it was opened at, matched after stripping Markdown marks, HTML tags, and table rules and counting repeats, and marks that row with `›` in a two-column gutter; with no match it marks the first row of text and stays at the top, and the notice says which happened. The page drops the trailing padding cells that the renderer adds to every row. `v` shows the source at that line. A switch is remembered for that file while the workspace runs and is not saved. See [0090](../decisions/0090-rendered-markdown-sources.md) and [0120](../decisions/0120-markdown-first.md). Tokenization uses the whole bounded source file to retain multiline lexical context. The source view shows the whole file and scrolls to the cited line with 12 rows of context above it, so the top of the file stays reachable.

Failed turns show recovery guidance and keep the current draft. `Esc` or `Ctrl+C` cancels a running turn; `Ctrl+R` retries the same intent. `Ctrl+Q` exits. Completed replies save before display. Drafts are kept while navigating within a running interface; they are not saved across process exits.

Only real terminal input and output select the workspace. `--plain`, pipes, redirected output, `TERM=dumb`, and `--ask` retain the line-based behavior. Plain mode is also the screen-reader option. The workspace detects terminal background color, supports `NO_COLOR`, and uses words as well as colors for status and assessments. See [0020](../decisions/0020-interactive-terminal.md).

The tab bar names four activities: Home, Course, Quiz, and Progress. Course covers the lesson, Topics, Sources, and source files. Sources is a sub-page reached with Ctrl+S and has no tab. Quiz covers the question and its index. Help and About highlight no tab. Each tab is a filled block, accent for the active tab and muted for the others, with text in the terminal's own background color, or near-black or near-white when the terminal does not report one. With no color the active tab is bracketed and underlined. The tab line ends with a right-aligned `Tab Next` hint. Each shortcut has one home: the action line holds the next-step choices, the sidebar holds the navigation reference in bold keys and muted labels, the input frame holds the typing keys for the box on its bottom border, and the footer keys line holds the app-wide keys (`F1 Help`, `F2 Settings`, `F3 About`, `Esc`, `Ctrl+Q`), with `Ctrl+K` and `Ctrl+S` added when the terminal is too narrow for the sidebar. The answer box has its title on its top border and its keys on its bottom border, has no placeholder, takes `Enter` to send with no manual new line, wraps softly, grows from one row to six, and turns pasted line breaks into spaces; see [0330](../decisions/0330-input-frame.md). Notices say what happened ("Lesson ready", "Answer reviewed") and never say turn. See [0310](../decisions/0310-controls-and-notices.md). The tab style follows the Tab style setting: none, block, slanted, rounded, or one of three joined styles. The slanted and rounded styles and the joined styles draw with Powerline glyphs. A joined bar has no gaps, steps its inactive tabs along a grey gradient so each separator shows, and starts at the first column of the terminal. A thin rule at the top edge of the row under the bar replaces the blank row: it is a dim grey with an accent stretch under the active tab, and all grey when no tab is active. The stretch covers the label, the whole cell for slanted tabs, and the left separator plus the label for joined tabs. Rounded tabs draw no rule. The default tab style is None. See [0210](../decisions/0210-filled-tabs.md), [0230](../decisions/0230-settings-page.md), and [0250](../decisions/0250-joined-tab-styles.md), and [0260](../decisions/0260-tab-rule.md). Tab and Shift+Tab step through the four and open each one's main page. A source file remembers the list that opened it, and Enter or Esc returns there. See [0190](../decisions/0190-course-and-quiz-tabs.md) and [0200](../decisions/0200-enter-closes-a-source-file.md). A session with no turns opens on Home, the first tab. Home shows the session goal under its opening text, and so does Progress, as its first block; the header holds only the brand and the agent status. See [0270](../decisions/0270-goal-on-home-and-progress.md). The first run asks "What do you want to learn?" on Home before anything is generated: the bottom box takes the goal, Enter on an empty box keeps the default, and every key except typing, Enter, quit, F1, F2, and F3 is held with a notice. The overview starts only after the answer, and `goal_chosen` in the session records it. See [0280](../decisions/0280-ask-for-the-goal.md). Home makes no model request. It lists Course and Topics, offers Check what you know once the overview is open and until a probe has run, offers Refresh the overview while the saved overview is out of date, always ends with About, adds Quiz once a quiz exists, adds Progress once there is an outcome, and adds Continue while an answer awaits review. `tutor.Recommend` picks one entry from saved state and Home puts it first with its reason. Enter opens the selected entry, number keys open an entry by position, and `/home` returns. A saved overview loads at once; otherwise the overview generates in the background while Home stays on screen. A session with turns resumes on Learn. See [0080](../decisions/0080-landing-page.md).

the About entry on Home and `F3` from any page open the About page, and `repo-tutor --version` prints the same build facts as plain text. Both read `about.Read`, which uses the Go build information: module version, commit revision, commit time, and platform. A build without version control data prints `unknown` for those fields. The page adds the session's agent and model. `NOTICES.txt` embeds the license text of every linked third-party module; `just notices` regenerates it, `repo-tutor --version --notices` prints it, and a test fails when a linked module is missing from it. The About page shows an 80-column color painting above the text when the terminal is at least 113 columns wide, it reports 256 colors or more, and `NO_COLOR` is unset. The art is embedded as `internal/about/splash.ansi`. See [0100](../decisions/0100-about-page.md).

Esc and a page's own key return to the page that opened it, either Home or the lesson. The workspace keeps one origin and does not save it; opening another secondary page directly keeps the original origin, and `Ctrl+L` always returns to the lesson. See [0110](../decisions/0110-page-origin.md).

Every page that opens from a key closes with that key. Ctrl+K, Ctrl+S, Ctrl+B, Ctrl+P, F1, F2, and F3 each open their page and, pressed again on it, return to the origin. Enter follows the same pairing on lists: it opens the selected item, and on an opened source file it closes the file and returns to its list. Esc closes any secondary page and is the one key that always goes back. A key that opens a page never has a different key as its only way out. See [0110](../decisions/0110-page-origin.md) and [0200](../decisions/0200-enter-closes-a-source-file.md).

## Repository snapshot

The reader walks the selected directory without following symlinks. It includes Go, Python, JavaScript, TypeScript, Markdown, and the `go.mod`, `pyproject.toml`, and `package.json` manifests. Hidden directories, dependencies, fixtures, and generated output directories are excluded. Git ignore rules apply when Git is available. Generated Go source is excluded from package analysis.

Files over 512 KiB or containing non-text data are skipped with a warning. The total source budget is 64 MiB. Read errors and an empty supported source inventory fail the scan with an explanation. The scanner does not execute the target's code, fetch dependencies, or contact a remote service.

Go packages use syntax trees across all build tags. Nested Go modules use their nearest `go.mod`. Test files are indexed separately and do not add production dependency edges. Python and JavaScript/TypeScript use conservative text patterns for imports and declarations. Python script registrations and main guards supply entry locations. JavaScript entry discovery is incomplete. Relative imports and a subset of local workspace imports can resolve; aliases, dynamic imports, and re-exports may be absent.

Topics begin with an overview, followed by source directories with their known dependencies first. Import cycles use a deterministic traversal; no order can place every edge of a cycle after its dependency. The map represents imports, not runtime calls.

## Grounded turns

Each turn includes the repository inventory, goal, current topic, pending question, previous reply, reading hints, and up to 48,000 bytes of numbered source excerpts. Named files in a learner's message get priority, followed by the current topic and its dependencies, architecture documents, entry points, and other sources. An excerpt can start near an entry point or a hotspot instead of line one. The inventory can include more files than the excerpts.

The prompt also supplies the latest saved lesson for the chosen topic, separately from the previous reply. Quiz instructions require questions at the taught level: a package overview does not prepare the learner to name unexplained implementation and test files. New exercises must supply any missing context. Debugging exercises state a concrete input, expected behavior, and observed failure, with hypothetical failures identified as such. Questions ask for one bounded result and must distinguish reasonable alternatives. Probes may test prior knowledge without a lesson, but still require clear questions.

Clarification requests receive no grade and keep the exercise open. When ambiguity requires rephrasing, the quiz index updates the current question without completing it; the revised question can then be answered normally. These prompt instructions guide the agent's judgment. Citation and format validation do not prove that a question is pedagogically sound.

The agent must return an explanation, question, assessment, feedback, and citations in a JSON schema. A lesson or quiz must include a question. Every reply must cite at least one line inside the supplied excerpts. The boundary rejects invented paths, out-of-window lines, missing fields, unknown grades, and unsolicited grading. Existence checks cannot prove that a cited line supports a claim; the learner can inspect it with `/read`.

Each accepted reply saves before display. Reading a lesson increments a lesson count. Only a reply that grades an attempted answer to a pending question changes correct, partial, or incorrect counts. Questions and hints should receive no grade. `/review` picks the largest positive total of partial plus incorrect answers minus correct answers. Outcomes remain the agent's judgments.

## Agent processes

Both drivers receive prompts on standard input in a dedicated session workspace outside the target. Prompts are never interpolated into a shell command. The driver reads streamed events and displays the completed reply after validation.

Codex uses `exec` and resumes the exact thread ID. It ignores user configuration and rules while preserving CLI authentication, disables shell and multi-agent tools and web search, and uses a read-only sandbox. A custom provider configuration is outside this first slice; `--model` supplies an explicit model choice.

Claude uses print mode with a structured schema, safe mode, no built-in tools or MCP servers, disabled hooks, and no project settings. It resumes the exact returned session ID. Safe mode preserves subscription authentication; bare mode would require different authentication behavior. Both integrations were checked against their installed CLI help and the official [Codex non-interactive documentation](https://developers.openai.com/codex/noninteractive) and [Claude headless documentation](https://code.claude.com/docs/en/headless).

No driver uses an ambiguous latest-session flag or bypasses permissions. A process error, failed event, timeout, truncated response, or invalid lesson leaves completed progress unchanged. An interrupted remote turn can still exist in the agent's own history. Resume failures are reported; `--new` starts a separate conversation.

The workspace passes the renderer `TERM=vt100` and the color profile detected from the real environment, so redraws avoid backward tabs and other optional cursor sequences that some IDE terminals mishandle. See [0130](../decisions/0130-plain-cursor-movement.md).

Picking a topic that already has a saved turn resumes it with no request. The workspace makes it the current topic, appends a copy of that topic's latest turn so the composer and the next prompt work from it, and restores its pending question or review stage. Quiz and probe state end, and progress does not change. The Topics list opens on the current topic and the quiz index on the active question, so a learner far down a long course does not start at the top. A topic with no saved turn opens its cached first lesson when the fingerprint matches the current source, and requests one otherwise. Ctrl+N and the Topics list share this path. See [0140](../decisions/0140-resume-topic.md).

## Lesson cache

A first lesson is saved as `lesson-<goal key>-<topic key>.md` beside `session.json`, one file per goal and topic. A header comment holds the topic, source fingerprint, question, and citations, and the body is the lesson Markdown. The opening overview and every first lesson that a learner requests are saved this way. A new session loads the overview from this file instead of requesting a turn, and records it as a lesson. When the fingerprint differs, the saved overview still opens with a notice, and `/refresh` requests a new one. A damaged or unknown-format file counts as missing. See [0070](../decisions/0070-overview-cache.md) and [0150](../decisions/0150-prefetch-next-lesson.md).

## Understanding score

A topic's understanding is its latest finished quiz: correct earns 1, partial earns a half, incorrect and skipped earn 0, divided by the quiz goal. A topic stores `quiz_credit` in half points and the `quiz_goal` it was earned against, written when the last answer of a quiz is recorded and again when a skipped question is re-answered. A quiz in progress leaves the stored score alone, and a topic the probe marked known counts as 100% until a quiz replaces it. Progress and the sidebar show coverage (topics read of all topics) and understanding (the mean over topics read, with an unquizzed read topic at 0%). A score under 60% makes a topic the one Home offers to review. The bands are solid at 80% and over and developing from 60%. See [0340](../decisions/0340-understanding-score.md).

## Settings

`internal/settings` holds the settings value, its defaults, and a decoder and encoder with no input or output. `session.LoadSettings` and `session.ChangeSettings` read and write `settings.json` in the same base directory as the session folders, found by `session.Base`. A missing file gives defaults, a broken file gives defaults and is moved to `settings.json.bad` on the next save, and a file from a newer version is read and never written over. A change re-reads the file and replaces only the field it changes. `F2` and the Settings entry on Home open the Settings page, a list of choices under Tab style, Markdown files open, Quiz length, and Highlight color. The highlight is one of the seven brand accents, green by default. `readableOn` shifts the chosen color along its lightness until it reaches a contrast ratio of 4.6 against the terminal background, so the same choice is a lighter shade on a dark terminal and a darker one on a light terminal. Each swatch on the page shows the shifted color. Up and Down move, Space chooses, and a choice applies and saves at once. Each tab style row shows a sample drawn by the same function as the bar, and the Powerline rows say a patched font is needed. An unreadable or newer settings file shows its notice at startup and at the top of the page. See [0220](../decisions/0220-settings-file.md), [0230](../decisions/0230-settings-page.md), and [0240](../decisions/0240-highlight-colors.md).

## Prefetch

A few seconds after a turn finishes, the workspace checks the topic that Ctrl+N would open. When that topic has no saved turn and no fresh cached lesson, it asks the agent for the topic's first lesson in a separate agent session and saves the result to the lesson cache, with a muted spinner and "Preparing next lesson" at the bottom right. The prefetch waits for the same lock as every turn. Starting a foreground turn for another topic, or quitting, cancels it, and a cancelled prefetch is not counted as a failure. A request for the topic being prefetched waits behind it and then uses the lesson it saved; Esc stops both. A first-lesson turn always checks the lesson cache before asking the agent. A failed prefetch is not retried in the same run. Prefetching records nothing in progress or history. `--no-prefetch` turns it off, and plain mode never prefetches. See [0150](../decisions/0150-prefetch-next-lesson.md).

## Reading hints

The hints feed a course topic, "Where change happens", the last topic after the foundations. When that topic is the subject of a request, the excerpts open with the five highest hints at their lines, and the prompt asks the tutor to explain where change concentrates. There is no Hotspots page, and `/hotspots` opens that lesson in the full-screen interface. `scan` and the plain interface still print the ranked list. See [0290](../decisions/0290-hotspots-as-a-lesson.md).

Git history counts file appearances in at most 2,000 non-merge commits from the last 180 days. It reads local history only and does not follow renames. Missing Git history falls back to source signals. Shallow history can undercount changes.

Go branch counts include conditionals, loops, non-default switch and select cases, and boolean conjunctions and disjunctions. Python and JavaScript/TypeScript counts use text patterns, which can include strings or miss syntax. Counts aggregate across a file and are not per-function cyclomatic complexity.

The reading score is `(commits + 1) * (branch points + 1)`, with path order breaking ties. Tests and generated Go files do not rank as production hotspots. The raw counts and first branch location appear beside each hint so a learner can inspect the evidence. Hints help select a reading or testing exercise; they do not establish defects or a need to refactor.

## Session recovery

The canonical repository path selects the session directory. A nonblocking file lock prevents two tutors from updating it at once. Session files have private permissions and are replaced atomically after a successful write and sync. The terminal requires macOS or Linux for the file lock.

The source fingerprint includes file paths and contents, independent of Git history. Changed source starts a fresh course with the previous agent, model, and goal unless explicitly overridden. `previous.json` keeps one archived session. A fresh course keeps topic progress, including topics marked known, and drops the saved quiz, probe, and review state so stale assessments do not carry over to different source. The current transcript retains 200 turns, with a 16 MiB file limit. Corrupt or unsupported state requires `--new` rather than silently discarding progress.

In plain mode, Ctrl-D or `/quit` exits after completed work is saved, and Ctrl-C exits from an agent turn or an idle prompt. In the workspace, Ctrl-Q or `/quit` exits and Ctrl-C cancels an active turn, then exits when idle. A per-turn deadline defaults to three minutes. Failure messages retain the CLI diagnostics and explain how to retry.

## Verification

`acceptance/terminal_test.go` builds the actual binary and exercises both agent protocols through fake executables. It covers lesson, quiz, grading, source reading, topic changes, explicit resume, offline scans, failed turns, timeouts, source changes, archives, and interruption at the input prompt. Unit tests check nested modules, mixed language imports, source exclusions, Git history, excerpt budgets, citation validation, immutable progress, and session locking.

Interface model tests check terminal bounds, visible exit guidance, navigation without agent calls, retained drafts, topic filtering through resize, retries, and cancellation. Manual pseudo-terminal checks exercise actual raw input and rendering, including browsing during a turn, CLI failures, cancellation, saved progress, and resume. Visual captures belong in `output/`.

Live smoke checks use onboard-kit and repowise as read-only targets. Their transcripts and scan output belong in `output/` and are not committed. These checks supplement the reproducible fake-agent tests; account access is not a test prerequisite.
